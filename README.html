為什麼需要兩把 Key？

瀏覽器呼叫有 Referer header，可設 referrer 限制保護配額；Python server-side 呼叫沒有 Referer，若設限制 Google 會回 403。兩把分開才能同時滿足兩端安全需求。

Pipeline 說明

每個 Step 都是單一職責的 Python 腳本，輸出 JSON 供下一步讀取。

選擇步驟： Step 1 模擬資料 Step 2 ETL 清洗 Step 3 路線計算 Step 4 碳排計算

產出 120 筆 2024 年度運單，刻意注入真實髒資料特徵：

出貨日期
4 種格式混用（YYYY/MM/DD、MM/DD/YYYY 等），約 7% 遺漏
車種
6 種不同寫法（含簡體字、英文縮寫、噸位標記）
毛重
混合 kg / 噸 / 帶單位文字，約 5% 遺漏
司機自填距離
80% 空白，凸顯 API 距離計算的必要性

將髒資料標準化，並為每筆記錄打上品質旗標：

日期標準化嘗試 4 種格式解析 → ISO 8601；失敗 → WARN_DATE
車種標準化6 種寫法對應表 → HGV / LGV / LGV-S；未知 → WARN_VEHICLE
重量標準化自動識別 kg / 噸 / 文字單位 → 統一 kg；遺漏 → WARN_WEIGHT
OK所有欄位乾淨（98 筆） · WARN自動修正後仍可計算（19 筆） · ERROR無法修正，CO₂ = null（3 筆）

ROUTE_PROVIDER 環境變數控制使用哪個 provider：

mock（預設）

mock_provider.py

Quadratic Bezier 曲線 + Haversine × 1.30 道路係數

路徑點數：10–14 點，可離線執行

地圖呈現：平滑拋物線弧，不跟著道路走

routes（真實 API）

routes_provider.py

Google Routes API v2，真實公路距離與路網軌跡

路徑點數：1,000–2,000 點，需 API Key

地圖呈現：沿台灣實際公路彎折，可見國道交流道

兩個 provider 介面完全一致（相同函式簽名、相同回傳欄位）。切換 provider 只需改 .env 的 ROUTE_PROVIDER 值，下游腳本無需任何修改。

套用 DEFRA 2023 排放因子。計算公式：距離(km) × 載重(tonne) × 排放因子 = kg CO₂e

車種代碼排放因子版本
大型貨車（>7.5t）HGV0.150 kg CO₂e / tonne-kmDEFRA 2023 v1.4
中型貨車（3.5–7.5t）LGV0.300 kg CO₂e / tonne-kmDEFRA 2023 v1.2
小型貨車（<3.5t）LGV-S0.467 kg CO₂e / tonne-kmDEFRA 2023 v1.1

同步輸出 audit_trail.jsonl，每行一筆完整計算快照，格式直接相容 BigQuery 匯入。

2024 全年結果：總碳排 39,875 kg CO₂e（3 筆 ERROR 因重量缺失無法計算）

audit_trail.jsonl 說明

每行一筆完整 JSON，保存「當下那次計算的完整快照」。稽核員若質疑某筆碳排，可在此查到完整的輸入 → 公式 → 輸出。

每筆記錄的關鍵欄位

waybill運單號（如 TW-2024-00001）
vehicle_raw原始髒資料（如「大型貨车」）→ 保留存證
vehicle_typeETL 標準化後（HGV / LGV / LGV-S）
emission_factor實際使用的排放因子數值（如 0.15）
ef_version排放因子版本（DEFRA 2023 v1.4）
co2_kg最終計算結果（kg CO₂e）
api_ts路線 API 呼叫時間戳（ISO 8601）
pipeline_run_ts本次 Pipeline 執行時間 → Anti-tampering 時間戳
quality_flags陣列，如 ["WARN_DATE", "WARN_WEIGHT"]

資料品質演示 SQL（稽核員視角）

BigQuery 讓「資料是否可信」從口頭說明變成可執行的 SQL 查詢。

選擇查詢： Q1 品質全貌 Q2 問題類型 Q3 問題運單 Q4 因子版本 Q5 自動化證明 Q6 距離核算

Q1 — 整批資料的品質全貌是什麼？

SELECT quality_level,
       COUNT(*) AS cnt,
       ROUND(SUM(co2_kg), 1) AS total_co2_kg
FROM `YOUR_PROJECT.ghg_scope3_cat4.carbon_records`
GROUP BY quality_level
ORDER BY cnt DESC;

預期結果：OK=98（81.7%）· WARN=19 · ERROR=3。ERROR 的 co2_kg 為 NULL，已排除於總碳排之外。

Q2 — 資料問題的具體類型是什麼？

SELECT flag,
       COUNT(*) AS affected_records
FROM `YOUR_PROJECT.ghg_scope3_cat4.carbon_records`,
  UNNEST(quality_flags) AS flag
WHERE flag != 'OK'
GROUP BY flag
ORDER BY affected_records DESC;

quality_flags 是 BigQuery REPEATED STRING 欄位，可直接 UNNEST 展開，無需解析 JSON 字串。

Q3 — 哪些運單有問題、為什麼？

SELECT id, date, carrier, origin, dest,
       quality_flags, co2_kg
FROM `YOUR_PROJECT.ghg_scope3_cat4.carbon_records`
WHERE quality_level IN ('WARN', 'ERROR')
ORDER BY quality_level, id;

WARN 筆數仍有 co2_kg（ETL 自動修正後計算）；ERROR 筆數 co2_kg 為 NULL（缺少必要欄位）。

Q4 — 排放因子版本是否全批一致？

SELECT ef_version,
       COUNT(*) AS cnt,
       ROUND(SUM(co2_kg), 1) AS total_co2_kg
FROM `YOUR_PROJECT.ghg_scope3_cat4.carbon_records`
GROUP BY ef_version;

全部 120 筆均應為 DEFRA 2023 v1.4，證明計算標準一致，無版本混用。

Q5 — 計算是自動化執行的，還是人工輸入的？

SELECT
  MIN(pipeline_run_ts)             AS pipeline_start,
  MAX(pipeline_run_ts)             AS pipeline_end,
  COUNT(DISTINCT pipeline_run_ts) AS distinct_run_batches,
  COUNT(*)                          AS total_records
FROM `YOUR_PROJECT.ghg_scope3_cat4.audit_trail`;

distinct_run_batches = 1 代表全部 120 筆來自同一次 Pipeline 執行，非事後逐筆手輸。

Q6 — 距離數字可以獨立核算嗎？

SELECT id, carrier,
       distance_km                               AS pipeline_km,
       ROUND(ST_Length(route_polyline) / 1000, 1) AS geography_km,
       ABS(distance_km - ST_Length(route_polyline) / 1000) AS diff_km
FROM `YOUR_PROJECT.ghg_scope3_cat4.carbon_records`
ORDER BY diff_km DESC
LIMIT 10;

route_polyline 是 GEOGRAPHY 型別，ST_Length() 直接計算球面距離（公尺）。差異來自球面距離 vs 道路係數 × 1.30。

安全設計

API Key 永遠不出現在任何原始碼或版本歷史中。只在 runtime 注入：

.env存放 GOOGLE_MAPS_API_KEY + GOOGLE_ROUTES_API_KEY，已列入 .gitignore
server.js啟動時從 .env 讀取 Key，注入 HTML 的 YOUR_API_KEY 佔位符
audit-control-tower.html原始碼只含 YOUR_API_KEY 與 __PIPELINE_DATA__ 佔位符，不含任何真實 Key
瀏覽器收到注入後的 HTML，在 runtime 使用 GOOGLE_MAPS_API_KEY 呼叫地圖 API
Fail-Fast

server.js 啟動時若 Key 或 Pipeline 資料缺失，立即報錯退出，不以空白或錯誤狀態繼續運行。

真實性Pipeline 全自動計算，pipeline_run_ts 證明數字由自動化產出、非事後手改（Anti-tampering）
可回溯性audit_trail 保留排放因子版本、計算時間戳、原始輸入值；可逐筆重現計算過程
標準化符合 GHG Protocol Scope 3 Activity-based 計算方法，DEFRA 2023 排放因子版本明確標記

傳統存證：稽核員索取截圖 → 無法排除人工編輯風險，且 100 張截圖無法系統化查詢。
本系統：稽核員跑一條 SQL → 可系統化驗證全部 120 筆，且每筆都有不可篡改的數位軌跡。
