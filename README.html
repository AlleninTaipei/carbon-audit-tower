核心理念

以動態數位軌跡取代靜態截圖存證，保留 Polyline 座標字串與 API 時間戳記，符合 ISAE 3410 對數位審計軌跡的要求。

需要 Python 3.11+ 與 Node.js 20.6+。BigQuery 上傳額外需要 google-cloud-bigquery。

# 必要套件
pip3 install openpyxl requests

# BigQuery 上傳（選用）
pip3 install google-cloud-bigquery

建立 .env 檔（已列入 .gitignore，不進版本控制）。需要兩把不同的 Google API Key：

ETL 清洗（etl_clean.py）

2024 全年結果：OK=98 · WARN=22 · ERROR=0

清洗項目邏輯

稽核意義

每筆記錄的 routeSource 欄位（MOCK_v1 或 ROUTES_API_v2）會寫入 audit_trail.jsonl，稽核員可查知每筆碳排的路徑資料來源。

碳排計算（calculate_carbon.py）

排放因子來源：DEFRA 2023。公式：距離(km) × 載重(tonne) × 排放因子 = 碳排量(kg CO₂e)

車種排放因子版本
大型貨車（HGV >7.5t）0.150 kg CO₂e / tonne-kmDEFRA 2023 v1.4
中型貨車（LGV 3.5–7.5t）0.300 kg CO₂e / tonne-kmDEFRA 2023 v1.2
小型貨車（LGV <3.5t）0.467 kg CO₂e / tonne-kmDEFRA 2023 v1.1

2024 全年結果：總碳排 39,875 kg CO₂e（3 筆因重量缺失無法計算，已標記 ERROR_NO_CO2）。同步產出 audit_trail.jsonl，每行一筆 JSON，格式相容 BigQuery 直接匯入。

稽核員最常問的六個問題

查詢： Q1 品質全貌 Q2 問題類型 Q3 問題運單 Q4 版本一致性 Q5 自動化驗證 Q6 距離核算

Q1 — 整批資料的品質全貌是什麼？

SELECT quality_level,
       COUNT(*)             AS cnt,
       ROUND(SUM(co2_kg),1) AS total_co2_kg
FROM `YOUR_PROJECT.ghg_scope3_cat4.carbon_records`
GROUP BY quality_level
ORDER BY cnt DESC;
預期結果：OK=98（81.7%）、WARN=19、ERROR=3。ERROR 的 co2_kg 為 NULL，已排除於總碳排之外。

Q2 — 資料問題的具體類型是什麼？

SELECT flag,
       COUNT(*) AS affected_records
FROM `YOUR_PROJECT.ghg_scope3_cat4.carbon_records`,
  UNNEST(quality_flags) AS flag
WHERE flag != 'OK'
GROUP BY flag
ORDER BY affected_records DESC;
quality_flags 是 BigQuery REPEATED STRING 欄位，可直接 UNNEST 展開，無需解析 JSON 字串。

Q3 — 哪些運單有問題、為什麼？

SELECT id, date, carrier, origin, dest,
       quality_flags, co2_kg
FROM `YOUR_PROJECT.ghg_scope3_cat4.carbon_records`
WHERE quality_level IN ('WARN', 'ERROR')
ORDER BY quality_level, id;
WARN 筆數仍有 co2_kg（ETL 自動修正後計算）；ERROR 筆數 co2_kg 為 NULL（缺必要欄位，無法計算）。

Q4 — 排放因子版本是否全批一致？

SELECT ef_version,
       COUNT(*)             AS cnt,
       ROUND(SUM(co2_kg),1) AS total_co2_kg
FROM `YOUR_PROJECT.ghg_scope3_cat4.carbon_records`
GROUP BY ef_version;
預期全部 120 筆均為 DEFRA 2023 v1.4，證明計算標準一致，無版本混用。

Q5 — 計算是自動化執行的，還是人工輸入的？

SELECT
  MIN(pipeline_run_ts)            AS pipeline_start,
  MAX(pipeline_run_ts)            AS pipeline_end,
  COUNT(DISTINCT pipeline_run_ts) AS distinct_run_batches,
  COUNT(*)                        AS total_records
FROM `YOUR_PROJECT.ghg_scope3_cat4.audit_trail`;
distinct_run_batches = 1 代表全部 120 筆來自同一次 Pipeline 執行，非事後逐筆手輸。pipeline_run_ts 即為 Anti-tampering 時間戳。

Q6 — 距離數字可以獨立核算嗎？

SELECT id, carrier,
       distance_km                              AS pipeline_km,
       ROUND(ST_Length(route_polyline)/1000, 1) AS geography_km,
       ABS(distance_km - ST_Length(route_polyline)/1000) AS diff_km
FROM `YOUR_PROJECT.ghg_scope3_cat4.carbon_records`
ORDER BY diff_km DESC
LIMIT 10;
route_polyline 是 GEOGRAPHY 型別，ST_Length() 直接計算球面距離（公尺）。差異來自球面距離 vs 道路係數（×1.30）。

系統三層架構

各元件分屬三個層次，服務不同角色、回答不同問題。

第一層｜GHG 盤查基礎設施（本專案核心）
Pipeline → ETL → Routes → 碳排計算 → BigQuery
問的是：「這批排放數字正不正確？」
使用者：碳盤查人員、資料工程師
第二層｜稽核驗證
HTML Control Tower + audit_trail
問的是：「數字可不可信、有沒有被篡改？」
使用者：ISAE 3410 稽核員、外部查驗機構
第三層｜管理決策（Looker Studio — 待實作）
已驗證的排放數據 → 行動情報
問的是：「要在哪裡改善？改善策略有沒有奏效？」
使用者：永續長、物流主管、決策層
