為什麼要做碳排放申報？

台灣企業面臨來自法規、市場與供應鏈的多重壓力，以下四個驅動力共同構成申報的必要性。

法規義務
《氣候變遷因應法》（2023）
主管：環境部氣候變遷署
對象：特定行業、大型排放源
重點：GHG 盤查申報義務；碳費計算基礎
資本市場
上市櫃永續報告書規範
主管：金融監督管理委員會
對象：上市櫃公司（分批強制）
重點：投資人導向的 ESG 揭露，8 月前公告
財務成本
碳費制度（2025 年起計費）
主管：環境部
對象：年排放 >25,000 噸 CO₂e
重點：排放量直接影響企業財務成本
供應鏈壓力
歐盟 CBAM（碳邊境調整機制）
主管：歐盟執委會
對象：出口歐盟的製造商及其供應鏈
重點：供應鏈客戶要求供應商揭露 Scope 3
重要提醒

即使企業本身不是「法規義務人」，大型客戶（尤其跨國企業）也可能透過採購合約要求供應商提供碳排數據。Scope 3 Category 4（上游運輸）正是供應鏈客戶最常要求揭露的類別之一。

關於 ISAE 3410

ISAE 3410 是什麼

第三方查驗機構在出具「溫室氣體報告保證聲明」時遵循的審計準則，由 IAASB（國際審計與確信準則委員會）制定。

查驗機構的方法論，不是政府命令。

兩種確信等級

有限確信（Limited Assurance）
查核範圍較窄，常見於首次查驗。

合理確信（Reasonable Assurance）
更深入的原始數據抽查，對數位稽核軌跡要求更高。

本系統的角色

本系統產出的 audit_trail.jsonl 正是為了滿足查驗機構在做 ISAE 3410 查驗時所需的：原始值、計算分解、排放因子版本、路線資料來源、時間戳記。

範圍邊界

本系統僅負責 Scope 3 Category 4（上游運輸）。Scope 1、Scope 2 及其他 Scope 3 類別，需由公司另行收集與計算。

通常使用 GHG 盤查軟體（如 Persefoni、Net Zero Cloud）或自建 Excel 模板完成彙整，最終輸出完整的 GHG 盤查報告書。

委託查驗機構進行 ISAE 3410 查驗

環境部認可的查驗機構（如 SGS Taiwan、DNV、Bureau Veritas、TÜV Rheinland、BSI Taiwan）會審查：

原始數據
抽查特定運單的原始 Excel vs 清洗後記錄（vehicle_raw vs vehicle_type）
排放因子
確認 ef_version 對應正確（DEFRA 2023 v1.4 / v1.2 / v1.1）
計算方法
驗算距離 × 載重 × 排放因子的計算邏輯是否符合 GHG Protocol
數據來源
確認 routeSource（MOCK_v1 / ROUTES_API_v2）與 api_ts 的一致性

查驗完成後出具「查驗聲明書（Verification Statement）」，附於盤查報告之後。

本系統在申報鏈中的定位

本系統是 GHG 盤查的資料來源子系統，專責 Scope 3 Category 4（上游運輸）。

本系統負責的

✓ Scope 3 Cat.4 活動數據自動化收集

✓ 路線距離計算與查驗（Mock / Google Routes API）

✓ DEFRA 排放因子套用與版本追蹤

✓ 數位稽核軌跡（替代截圖）

✓ 數據品質旗標（WARN / ERROR）

本系統不負責的

✗ Scope 1、Scope 2、其他 Scope 3 類別

✗ 全公司 GHG 盤查彙整

✗ 查驗聲明書出具

✗ 向主管機關正式申報

✗ 最終報告簽署
