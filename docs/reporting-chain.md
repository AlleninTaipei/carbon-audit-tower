# 申報鏈：數字從計算到揭露的完整路徑

本文說明台灣碳排放申報的法規脈絡、揭露路徑，以及本系統在整個申報鏈中的定位。

---

## 為什麼要做碳排放申報？

### 法規驅動力

| 法規 / 要求 | 主管機關 | 適用對象 | 重點 |
|------------|---------|---------|------|
| 《氣候變遷因應法》（2023）| 環境部氣候變遷署 | 特定行業、大型排放源 | GHG 盤查申報義務；碳費計算基礎 |
| 上市櫃永續報告書規範 | 金融監督管理委員會 | 上市櫃公司（分批強制）| 投資人導向的 ESG 揭露 |
| 碳費制度（2025 年起計費）| 環境部 | 年排放 >25,000 噸 CO₂e | 排放量直接影響企業財務成本 |
| 歐盟 CBAM（碳邊境調整機制）| 歐盟執委會 | 出口歐盟的製造商及其供應鏈 | 供應鏈客戶要求供應商揭露 Scope 3 |

> **重要**：即使企業本身不是「法規義務人」，大型客戶（尤其跨國企業）也可能透過採購合約要求供應商提供碳排數據。

## 誰是真正的「審視者」？

```
這個系統的稽核資料 ──→ 第三方查驗機構（SGS / DNV / Bureau Veritas 等）
                              ↓ 出具查驗聲明書
              ┌───────────────┴────────────────┐
              ↓                                ↓
        環境部氣候變遷署                  金管會 / 台灣證交所
      （GHG 盤查申報系統）              （永續報告書公開平台）
              ↓                                ↓
        碳費計算 / 法遵               投資人 / ESG 評等機構
                                    (MSCI / Sustainalytics / CDP)
```

### 關於 ISAE 3410

ISAE 3410 是**第三方查驗機構**（如 SGS、DNV）在出具「溫室氣體報告保證聲明」時遵循的審計準則，由國際審計與確信準則委員會（IAASB）制定。

它不是政府機關的行政命令，而是：
- 查驗機構用來評估「這份盤查報告可不可信」的方法論
- 分為**有限確信（Limited Assurance）**和**合理確信（Reasonable Assurance）**兩個等級
- 後者要求更深入的原始數據抽查，對數位稽核軌跡的要求更高

本系統產出的 `audit_trail.jsonl` 正是為了滿足查驗機構在做 ISAE 3410 查驗時所需的：原始值、計算分解、排放因子版本、路線資料來源、時間戳記。

## 兩條揭露路徑

### 從本系統到最終申報的完整流程

```
[Step 1] 本系統輸出
    carbon_audit_records.json  ←── Scope 3 Cat.4 活動數據
    audit_trail.jsonl          ←── 查驗機構稽核依據

    ↓

[Step 2] 彙整進全公司 GHG 盤查報告
    Scope 1（直接排放：公司自有車隊、廠房）
    Scope 2（電力購買）
    Scope 3（價值鏈排放，本系統負責 Category 4）
    → 通常使用 GHG 盤查軟體或 Excel 模板完成

    ↓

[Step 3] 委託查驗機構審查（ISAE 3410）
    查驗機構抽查原始數據、排放因子依據、計算方法
    → 本系統提供：路線座標、距離計算方式、DEFRA 版本號、質量旗標
    → 出具「查驗聲明書（Verification Statement）」

    ↓

[Step 4A] 環境部申報路徑              [Step 4B] 金管會揭露路徑
    提交 GHG 盤查報告                    永續報告書（含碳排章節）
    至環境部氣候變遷署                    公告於台灣證交所 ESG 平台
    碳費計算依據                          8 月前公告（上市公司時限）
```

## 本系統在申報鏈中的定位

本系統是 GHG 盤查的**資料來源子系統**，專責 Scope 3 Category 4（上游運輸）。

| 本系統負責的 | 本系統不負責的 |
|-------------|--------------|
| Scope 3 Cat.4 活動數據自動化收集 | Scope 1、Scope 2、其他 Scope 3 類別 |
| 路線距離計算與查驗 | 全公司 GHG 盤查彙整 |
| DEFRA 排放因子套用與版本追蹤 | 查驗聲明書出具 |
| 數位稽核軌跡（替代截圖） | 向主管機關正式申報 |
| 數據品質旗標（WARN / ERROR）| 最終報告簽署 |

### 傳統作法 vs 本系統

| | 傳統作法 | 本系統 |
|-|---------|-------|
| 路線距離佐證 | 地圖截圖（靜態圖片）| 路線座標字串（可重新渲染驗證）|
| 排放因子追蹤 | Excel 欄位備註 | 每筆記錄攜帶版本號（v1.4 / v1.2）|
| 數據來源 | 人工填寫 | API 時間戳記（api_ts 欄位）|
| 查驗機構抽查 | 逐一比對截圖與計算 | 程式化查詢 audit_trail.jsonl |

## 申報週期示意

```
1–3 月   收集上一年度活動數據
         ← 本系統：全年自動記錄，年底匯出即可

4–6 月   完成全公司 GHG 盤查計算與內部審查

6–7 月   委託查驗機構進行 ISAE 3410 查驗
         ← 查驗機構可直接查詢 audit_trail.jsonl

8 月前   永續報告書公告（金管會要求的上市公司時限）

全年持續  環境部盤查申報（依規模 / 行業別，部分為即時申報）
```
